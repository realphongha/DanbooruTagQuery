# Anime Image Tagger Prototype — Training Pipeline

## Objective

Train a lightweight multi-label anime image tagger using a pretrained Vision Transformer backbone and a simple linear classification head.

This prototype is intended to validate the complete data pipeline before implementing the proposed Tag Query Decoder architecture.

---

# Dataset

The training data is stored as a Parquet file with the following schema:

| Column | Description |
|---------|-------------|
| `id` | Danbooru post ID |
| `media_asset_created_at` | Creation timestamp |
| `score` | Danbooru score |
| `rating` | Image rating (`g`, `s`, etc.) |
| `media_asset_file_size` | Original file size |
| `tag_string_general` | Raw general tags |
| `tag_string_character` | Raw character tags |
| `tag_string_copyright` | Raw copyright tags |
| `image_url` | URL to the downloaded 360px image |
| `tags` | List of filtered tags used as labels |

We use `tags` for training.
The prototype uses a fixed vocabulary of **50 tags**.
We start with `data/danbooru2025_lite_train.parquet` and `data/danbooru2025_lite_val.parquet` first.

# Image Downloader

## Goal

Download all images referenced in the Parquet dataset using concurrent HTTP requests.
Run this if `data/images/` does not have the same data as Parquet files. 

---

## Input

Parquet file containing

- `id`
- `image_url`

---

## Output

```
data/images/

├── 123456.jpg
├── 123457.webp
├── 123458.png
...
```

The filename should be the Danbooru `id`, preserving the original file extension.

---

## Requirements

### Concurrency

Use

- `concurrent.futures.ThreadPoolExecutor`

Maximum workers

```python
32
```

Make this configurable.

Since downloading images is network I/O bound, threads are appropriate.

---

### HTTP

Use a single shared

```python
requests.Session()
```

for connection reuse.

Each worker should use the shared session.

---

### Timeouts

Use

```python
timeout=(5, 30)
```

(connect timeout, read timeout)

---

### Retries

Retry failed downloads up to

```python
3
```

times with exponential backoff.

Retry only for network failures and HTTP 5xx responses.

---

### Skip Existing

Before downloading

```python
if file.exists():
    return
```

This allows interrupted downloads to resume safely.

---

### Saving

Infer the extension from the URL.

Examples

```
12345.jpg

12346.webp

12347.png
```

Write files in binary mode.

---

### Validation

After downloading

- verify HTTP status == 200
- verify file size > 0 bytes

Delete incomplete files if validation fails.

---

### Progress Bar

Display progress using

```python
tqdm
```

Example

```
Downloading images

18472 / 20000
```

---

### Logging

Track

- downloaded
- skipped
- failed

Print a final summary

```
Downloaded : 19891

Skipped : 102

Failed : 7
```

---

### Failed Downloads

Write failed IDs and URLs to

```
failed_downloads.csv
```

Columns

```
id

url

reason
```

---

### Image Paths

After downloading, create a new dataframe column

```
image_path
```

Example

```
data/images/123456.jpg
```

Save the updated parquet.

The training dataset should use `image_path` instead of `image_url`.

---

## Nice-to-have

Support Ctrl+C gracefully.

Already-downloaded files should remain untouched so the script can simply be rerun.

No duplicate downloads should occur.

# Backbone

Use a pretrained Vision Transformer from `timm`.

Preferred order:

- DINOv3 ViT-S
- TinyViT
- ViT-S

Remove the original classification head.

Output should be image features only.

---

# Classification Head

For the prototype, use a simple linear layer.

```text
Image

↓

ViT

↓

CLS embedding

↓

Linear

↓

50 logits
```

The rest of the pipeline should be written so this head can later be replaced with the proposed Tag Query Decoder without modifying the training loop.

---

# Loss

Use

```python
torch.nn.BCEWithLogitsLoss
```

because this is a multi-label classification task.

Do **not** use CrossEntropyLoss.

Later experiments may replace this with Asymmetric Loss.

---

# Design Goal

The training pipeline should be modular.

The only component that should change between experiments is the classification head.

Prototype

```text
ViT

↓

Linear Head
```

Research model

```text
ViT

↓

Tag Query Decoder
```

Everything else (dataset, dataloaders, optimizer, scheduler, metrics, logging, checkpointing, and evaluation) should remain identical.
